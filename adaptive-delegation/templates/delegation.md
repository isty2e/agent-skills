# Project Delegation Hints

Project-scoped routing evidence, subordinate to project instructions and authorized execution settings. Apply
`adaptive-delegation` when choosing or revising a hint. This file does not change model availability, pins, permissions,
budgets, or acceptance criteria.

## Current Hints

Use applicable entries together with current-session evidence. Without sufficient local evidence, use approved settings
and the skill's starting points.

## Entry Format

Add entries under Current Hints as useful observations arise. The format below is a blank example, not an active hint.
Keep one current choice per scoped routing decision and preserve the previous choice for rollback. Update existing
entries rather than appending every run; keep runtime details in approved task records.

```markdown
### <Task scope and routing decision>

- Applies to: <task family, relevant model/profile, host and prompt versions>
- Current choice: <direct/delegated work, partition, handoff, context, or allowed execution setting>
- Intended benefit and acceptable burden: <what this choice is meant to improve and its tradeoff>
- Evidence: <observed result, checks, parent repair, and approved record references; distinguish estimates>
- Counterevidence and uncertainty: <failures, missing data, limits, and confidence; label provisional choices>
- Previous choice: <choice to restore, or none if this is the first hint>
- Recheck: <next applicable task or other trigger; evidence for keeping, revising, or reverting>
- Updated: <date and relevant settings version>
```

Preserve material corrections and contrary evidence when revising a choice. Do not put credentials, unnecessary source
content, or full transcripts here. Reading or updating this file does not authorize sharing it outside the project.
