# Project Delegation Experience

Project-scoped choices and observations, subordinate to project instructions and authorized execution settings. Apply
`adaptive-delegation` when deciding, recording, or reviewing experience. This file does not change model availability,
pins, permissions, budgets, or acceptance criteria.

## Current Hints

Use applicable entries together with current-session evidence. Without sufficient local evidence, use approved settings
and the skill's starting points.

## Hint Format

Add entries under Current Hints as useful observations arise. The format below is a blank example, not an active hint.
Keep one current choice per scoped routing decision and the previous choice for rollback. Update hints only when
warranted; retain new observations even when the current choice stays unchanged.

```markdown
### <Task scope and routing decision>

- Applies to: <task family, relevant model/profile, host and prompt versions>
- Current choice: <direct/delegated work, partition, handoff, context, or allowed execution setting>
- Intended benefit and acceptable burden: <what this choice is meant to improve and its tradeoff>
- Evidence: <observed result, checks, parent repair, and approved record references; distinguish estimates>
- Counterevidence and uncertainty: <failures, missing data, limits, and confidence; label provisional choices>
- Previous choice: <choice to restore, or none if this is the first hint>
- Recheck: <next applicable task or other trigger; evidence for keeping, revising, or reverting>
- Updated: <date and relevant settings version>
```

Preserve material corrections and contrary evidence when revising a choice. Do not put credentials, unnecessary source
content, or full transcripts here. Reading or updating this file does not authorize sharing it outside the project.

## Observations

Start pending before dispatch unless that write would violate an enforced launch precondition such as a clean source
checkout; then retain it in permitted session state and persist immediately after the launch attempt. Supplement after
execution and parent review without a reminder. Add actual entries here; the fenced format is not a run. Keep the core
fields with explicit unknowns/reasons rather than omitting executions. A fanout may share one decision entry with
identifiable children, attempts, and outcomes. Link full artifacts instead of copying them. Consolidate only under
`adaptive-delegation` while retaining covered identities and material evidence.

```markdown
### <Stable project-unique decision ID> — <date; pending, assessed, or incomplete with reason>

- Task: <family, scope, project revision/state, skill revision or unknown>
- Choice: <direct/delegated; expectation, acceptable burden, selection basis>
- Settings: <host/version, parent model; intended/effective child model/effort/context/concurrency/limits; unresolved
  values with reasons>
- Execution: <child/run/attempt IDs, status, retries/fallbacks/cancellation; reason if no child ID>
- Collection: <sources checked, lookup attempted/outcome, unavailable or skipped with reason>
- Measurements: <tokens/cache, cost or quota, duration; values/units, source, inclusion scope, unknowns with reasons;
  attributable parent checking/repair and time to acceptance>
- Parent assessment: <result, accepted unchanged/local repair/substantial rework/discarded/unused; checks, contribution,
  repair burden, uncertainty; pending or not applicable with reason>
- Next choice: <expectation met/unknown; keep/adjust/revert/gather evidence, rationale, hint/recheck reference>
```

Repeated completion notices update the same observation. Preserve original facts when correcting an assessment. No new
lesson is valid, not a reason to skip recording. Missing is not zero. Keep incomplete entries visible; do not mark an
observation assessed before accounting for parent verification or its absence.
